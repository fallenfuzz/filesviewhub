# A folder shows its subfolders as tiles; a lone folder gets no column

In the app, a folder with subfolders shows them as tiles first, then the Works it keeps itself
under "In this folder". This replaces the default of `decisions/2026/09/29/folder-shows-own-works-and-one-box-shape.md`, where a folder showed only its
own Works and its subfolders were reached through the folder columns. With the columns hidden
(autohide, a narrow window), that default left subfolders out of sight: a folder that kept a few
books of its own showed those books and nothing of the folders beside them. Tiles show what is
inside each subfolder, so the pane alone is enough to browse the whole library. Settings keeps
two choices: tiles, then own Works (the default), or every Work below.

A level of the open path that holds a single folder adds no folder column. A column is there to
move sideways between folders; one row has nothing beside it. That folder shows as a tile and in
the breadcrumb, and the next column's title names it.

## Considered Options

- Keep "Only what is kept in that folder" as a choice: with tiles shown in every case where it
  used to hide them, nothing is left that it does better.
- Tiles only, no folder columns: moving between sibling folders takes two clicks (up, then down)
  instead of one.
- Join a chain of single folders into one column row ("Books › Fiction"): one more kind of row
  to read, for the same reach the breadcrumb already gives.
