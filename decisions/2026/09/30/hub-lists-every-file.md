# The Hub lists every file, including the ones no Work links to

Every file in a Section folder is reachable from the Hub. A file that no Work links to is an
Unlisted file: the build lists it with one reason (not placed, unknown type, code and captions,
program folder), and the Hub shows all of them under Unlisted in the first column. A Settings
switch also shows them in place: in their folder, in the dialog of the Work whose folder holds
them, and in search. The build stops if the listed and linked files do not add up to every file
it walked, so a change to the build cannot quietly hide files again.

The Hub is where the collection gets checked and tidied, not only browsed. A catalog that drops
what it cannot place hides both gaps in the build (a PDF inside a course that no lesson picked
up) and problems in Dropbox (half-downloaded files, split archives, a folder of WAV tracks).
Listing them with a reason makes both visible without walking folders.

## Considered Options

- Keep printing them in the build report only: the person tidying Dropbox works in the Hub on
  Windows and never sees the build output.
- Show unlisted files as ordinary cards: they would take Marks, count as Works, and flood course
  folders with captions and code; a separate list with a reason keeps them diagnostic.
