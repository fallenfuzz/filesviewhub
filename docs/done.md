# FilesViewHub: what the app does

What is built, by area. What is left is in GitHub issues; decisions and their reasons are in
`decisions/`. An item goes here in the same change that builds it and closes its issue. The Hub page
is retired and not tracked here.

Catalog and folders
- Folder tree with checkboxes on any drive; a Section per top-most ticked folder (`decisions/2026/10/05/checked-folders-on-any-drive.md`); a whole drive takes a tick too and is then a Section named after its label, else its letter or mount point, with the keys a tick of its folders gives, so Marks stay either way; the system drive (and any letter with its serial, as a `subst` of it) and Computer take none and say Tick folders inside it; a drive mounted inside a ticked folder (a share in Linux Home) stays out of it and is ticked by itself; a drive's full label shows on hover; keys kept as `{serial}:/path` by a Linux Section at a mount point are rewritten on start, so Marks, Ticks, Review choices, Folder kinds and Undo stay (`decisions/2026/10/21/a-whole-drive-can-be-a-section-except-the-system-drive.md`)
- Section kind guessed (Courses, Books and documents, Collections, Videos and files, Photos) and changeable (`decisions/2026/10/05/section-kind-guessed-and-changeable.md`), a change of kind or Let the app guess again keeping its name as it was, so a name never chosen keeps following the folder's; a folder mostly of numbered page packs, as kids' activity sheets, is guessed as Collections
- Works by kind: lessons, formats of one book, folders as Works, Shelves (`decisions/2026/09/30/a-folder-is-a-work-or-a-place-never-both.md`); captions and code joined to their Work
- Section settings…, from the Section's menu (rail, columns, Home tile, the page's ⋯) or Settings… in Settings, Sections, which keeps only the list of Sections with each path, kind and where it shows, and the settings for all: a centred dialog with the name (editable) and path, the kinds on the left (a row of tabs below 820 px) and on the right How <kind> looks: one sample per view level of the kind picked, in the view used there now, drawn from made-up names (one of 60 characters, one in Cyrillic, one with an emoji; never the person's files), with the level's name and the view's, nothing to pick (`decisions/2026/10/21/the-view-menu-sets-each-folders-view.md`); arrow keys move through the kinds, and Left and Right between a Photos Section's two tabs; a name change alone is made in place, with no read; a change of kind is counted by a read-only dry run on the files read last time (the cards and the Marks set aside, no folder read, nothing saved), stopped when the dialog closes, then reads the Section again; Show inside lists each Section with its drive on the right; Save applies it and shows a toast with Undo (also Ctrl+Z) that puts back the name, kind and Show inside; it waits while folders are being read, and a read that fails puts the settings back and says so; an emptied name follows the folder's name again; a Section whose drive is not connected counts no Marks set aside; Cancel, the X and Esc change nothing and give focus back to what opened it. View's Subfolders sets how the open page shows its subfolders (`decisions/2026/10/21/the-view-menu-sets-each-folders-view.md`), offered only where it has some and, inside a folder, only where the app places that folder on disk (a Courses Section of courses, or a folder of only Works, has cards alone): the views the app draws (Rows that open, Folder tiles with a cover mosaic, the Works count and the name under it as Home's Your folders, Everything below; each one still to build is its own issue); at a Section's top it is the Section's view, kept per Section and level in settings.json (`views`); inside a folder it is that folder's own (on each drive of a merged Section), which the folders below take until one has its own, with Same as <the folder above, or the Section> and the view it gives first, which drops the folder's own; it only saves and redraws, with no read; settings kept with Every Work below picked for all give each Section Everything below once
- Folder kinds (`decisions/2026/10/14/a-folder-takes-its-own-kind-or-becomes-a-section.md`): Folder settings… on every folder's menu (columns, rows, tiles, the address bar's steps) is the Section settings dialog for one folder: no name field, the folder's name and path, the kinds with Same as <the folder above, or the Section> first, and How <kind> looks with the levels Inside a folder and One Work (or the four Photos levels) in the views used there; the nearest folder with a setting wins, for the kind and for each level's view; a folder with a kind is read as that kind from there down and stays a folder, never one card (`scan.rs` `holds_kind`); kept in settings.json by Drive and path (`folder_kinds`), one entry per folder whatever the case of its name, listed on "What this app does"; a folder's own view is set by View's Subfolders (above), kept in the same entry; a folder of a merged Section (Show inside) takes it on each drive, and two folders shown under one title ("01 Books" and "Books") take it both, read again together by a whole read, as Read this folder again does for them, and a folder with no view of its own takes the Section shown; a kind change is counted by a dry run of the Section's files with that folder's kind (`preview_folder`: its cards on every drive, the Marks set aside and the Orphaned Marks that come back, as Section settings now says too), then reads again the top folder holding it (the whole Section when the folder above takes its files, as a book's format folder), with a toast and Undo; Work ids do not change, so Marks stay on the Works still made and the rest are Orphaned Marks; a folder with a kind renamed or moved on disk loses it at the next read, with one toast (a folder the system cannot look at now keeps it); a folder that a read makes into one card, or that is gone, gives way to the nearest folder above it
- A Photos folder inside a folder Section (`decisions/2026/10/14/a-folder-takes-its-own-kind-or-becomes-a-section.md`): a folder whose Folder kind is Photos shows from there down as a Photos Section does (years, months, Events, the day panel, On this day, the Photos bar and filters), under its path in the address bar (Photos › Camera › 2021 › March), with the years and months in the folder columns; its Events stay in the Section, their ids use that folder in place of the Section's folder (`scan.rs` `photo_folder`), the same ids it would have as a Photos Section of its own, and a Folder kind below it is not used; Review (its notes, Copies and Similar shots, the Review chip, the filters' counts) and Move with its Undo cover that folder alone, moving into its own Not needed (`shots.rs` `places`); the Photos menus work there, a year or month offering Read this folder again; a kind change to or from Photos has the dry run, the read again and Undo of any Folder kind, and Marks on cards it no longer makes become Orphaned Marks that come back with Undo; Settings shows the Photos gap when any folder has Photos

a folder whose Split-out Section is gone from a connected drive shows as missing, as a gone checked folder does, with Remove this Section, and the Section it came from no longer links to it; unticking or removing the folder holding it drops it, and Remove's question names them; Make it a Section waits for a new kind's count (which says the Marks it sets aside), is off with a note for a folder in more than one place (a merged Section, two folders under one title) and while its drive is not connected, and is refused for a folder whose files belong to a card outside it (a book's format folder); Put back is off while its drive is not connected; Show inside of a Split-out Section leaves out the Sections it came from; "What this app does" lists it with the settings
- A Photos Section's Folders with other things (`decisions/2026/10/14/a-folder-takes-its-own-kind-or-becomes-a-section.md`): Section settings of a Photos Section has two tabs, How Photos looks and Folders with other things, the second listing its top-level folders by their names on disk with how many files each holds (Review's Not needed left out), each with a kind button that opens the app's menu (Same as <Section>, then the other kinds) and Make it a Section; the kinds picked are counted together by one dry run (`preview_folder` with `more`: their cards and the Marks set aside), applied with Save, which reads the Section again, with a toast and Undo; a folder named like a year or Undated keeps the Section's kind, as it would share its place with that year; Make it a Section waits until the other changes are used or cancelled and makes the folder a Section with its kind and views, as part 3 does, and a Photos folder put back is the Section's own again; a folder already split out shows as a Section of its own with its file count; - Suggest kinds for a Section's folders (`decisions/2026/10/14/a-folder-takes-its-own-kind-or-becomes-a-section.md`): the app's guess runs on each top-level folder of a Section, from the files read last time (`scan.rs` `offer`); a folder whose guess differs from the Section's kind and that holds at least 10% of the Section's files, or 50 files, is offered, except one the Section makes into one Work (a course in a Courses Section), one whose files are part of a card outside it (a book's `files` folder), one with a Folder kind of its own, one also in a Section shown with it (Show inside) and, in a Photos Section, a year, Undated, Not needed, a folder of only pictures or one of mostly camera pictures and clips (a folder of videos not named by a camera is offered); the offer is a notice at the top of that Section (and of each Section shown inside it), matching its offline notice, listing each folder by its title with the kind guessed and its file count, and the count of a dry run (`preview_folder`: the cards in those folders and the Marks set aside), with Set a kind per folder (each takes the kind guessed as its Folder kind, one read of the Section), Make each a Section (each a Split-out Section of that kind, one read; a guessed Section kind is kept as its own while they are out, so what is left is not guessed again, and the toast says so) and Keep one kind; the first two wait for the count (a failed count is tried again once, then offers Count again), and a second click while one is applied does nothing; the app applies neither by itself; each answer puts the offer away for that Section, kept in settings.json (`offered`, dropped with the Section, listed on "What this app does"), and its toast's Undo puts back the folders, the guessed kind and the offer; focus then moves to the page; Section settings' foot has Suggest kinds for its folders, which shows the offer again at the top of the Section, or says no folder looks like another kind
- A Work named only by its part ("CD1", "Disc 2", "Version 2", "Vol. 3", "Часть 1", a folder named by a number of up to three digits) is titled from the folder above, then the part: "The Time Machine - CD1"; a folder above named as a part or "Audio" is passed over
- A leading number ("1. ", "01 ", "2) ", "3 - "; not "3-D" or a lesson's own "2.1") is cut from a title, except where more than half of the folders, or of the files, side by side start with one: there every kind but Photos keeps it, so they read and sort in that order, 2 before 10 (`scan.rs` `numbered`); links to Split-out Sections and the offer of other kinds title their folders the same way, and so do folder headings inside a Work and the titles in a Work shown as a grid (a list of lessons or tracks numbers its rows itself); a Split-out Section with no name of its own is named as its row; a leading number stays on the line of the word after it

- Merged Sections across drives (`decisions/2026/10/05/checked-folders-on-any-drive.md`); copies of one Work (same place, same size) are one card naming both drives, and a different file at the same place names its own drive; the card shows the newest Mark of its copies and the Ticks of all of them (its progress line, its dialog and In progress), a Tick or Mark set on it lands on the copy with that Mark (else the first Section's), and an untick or a cleared Mark takes it off every copy, so one press leaves the card unticked or unmarked
- Read on start, by Read folders again, or one Section or folder at a time; a Section of 150,000 cards in one folder answers within 1 s of a read ending, on first open and after each read, and opens in under 1 s; a Section of 600,000 files in 6,000 folders on a network drive opens in about 0.5 s and its worst stall after a read is under 0.8 s on a built app; there Expand all opens its 2,000 folder rows in under 0.4 s, and opening a folder, Back, search, Folder tiles and Collapse all each stall under 1 s: the folder columns, rows and tiles come from one folder tree per Section and filter, an open row makes its tiles and cards only as it comes near the view, and a row out of sight is not laid out; and the built app reaches the core through Tauri's IPC protocol, not the slower postMessage; with real-length names that Section's catalog is 61 MB instead of 596 MB: the catalog file (version 3) leaves out each field the app can make again from the others, and the page gets each Section's Works in parts of 50,000, so a read reaches the page and the app starts again with it (Expand all and per-folder passes too); unlisted files are stored and sent the same way, in parts of 50,000, so a Section of 1,500,000 of them (778 MB in version 2, 234 MB in version 3) reaches the page in about 4 s, on a read and on start, and the reply sent first is under 1 KB; a catalog file of version 1 or 2 is written again as version 3 on the first start, only when the current form gives every Section back exactly, else it stays in its version
- Renaming or removing a Section keeps the window answering on a catalog of 1,500,000 files: the catalog is saved off the main thread, under its lock, so two changes in a row reach the file in order; a sync command waits at most 3 ms during the save (it waited 0.6 to 0.9 s)
- Folders moved, renamed or deleted shown as not found, with Tick its new place and Remove; folders on a drive not connected listed with what was read last time, browsable: such a Section, Split-out Section or folder shown inside one is greyed as a button that is off in the rail, the library column, Home's Your folders (its pictures without colour), a link to it in the Section it came from and Settings, Sections (where a line under its path says so at full contrast), each with "Its drive (<drive>) is not connected" on hover; the top of the Section says so, with Read this Section again (also in its menu while away), and a Section with a folder shown inside it that is not connected names that folder; opening a file there, or Show in File Explorer, shows a toast saying its drive is not connected; a drive unplugged while the app is open is found within 10 s or when the window gets focus (the drives are listed, no folder read and no network drive asked, so a Section on a network drive still mapped waits for Read folders again; `scan.rs` `mark_away`), and a drive back is read again by Read folders again
- StoredData and the cache never read as part of a ticked folder
